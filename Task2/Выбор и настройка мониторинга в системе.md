3 Мотивация:
На данный момент есть тольк овнешний мониторинг, который обеспечивает только внешний контроль  за работой сервисов.
Его не достаточно для для оперативного контроля всей инфраструктуры, невозможно оперативно выявить узкие места или локализовать место сбоя.
Это несет большие рсики возможности обеспечить требуемый SLA, тем более с учетом масштабной реорганизации и усложнении инфраструькуры.
Мониторинг позволит определить те части инфраструктуры котрые требуют оптимизации или масштабирования в первую очередь. 
Поможет предотвратить инциденты связанные с исчерапнаием ресурсов. Существенн сократит время рекции и локализации аварий. 
Что в конечном итоге положительн оскажется на пользовательсом опыте. 


4 Выбор  подхода к мониторингу:
Мониторинг можно разбить на 3 слоя:
1. Инфраструктурный - показатели работы инфраструктуры: Сервера, Сеть. Для этого слоя мониторинга лучше всего использовать подход  USE.
2. Системный - Показатели работы систем обеспечивающих работу приложения: PostgreSQL, RabbitMQ,S3. Для этого слоя лучше всего использовать подход RED
3. Прикладной - показатели самих приложений: Онлайн Магазин, CRM, MES.  Для данного слоя лучше всего использовать подход "Четыре золотых сигнала"

5 Описание метрик:
 5.1 Инфраструктурный мониторинг нужен  для контроля физических показателей инфраструткуры: Утилизация памяти, CPU, места на дисках и т.д.
Для всех  элементов инфраструктуры (серверов) необходимо  установить следующий набор метрик:
 CPU % -  Для контроля за утилизацией CPU. Метки: [CPU] [Сервис: Shop/MES/CRM] [Элемент инфрастрктуры: DB/APP/QUEUE/LB и т.д.] [Имя сервера]  
 Memory Utilisation - Контроль за утилизацие памяти Метки: [Memory Utilisation] [Сервис: Shop/MES/CRM] [Система: DB/APP/QUEUE/LB и т.д.] [Имя сервера]
 Disk Utilisation - Контроль за свободным местом на дисках. [Disk Utilisation ] [Сервис: Shop/MES/CRM] [Система: DB/APP/QUEUE/LB и т.д.] [Имя сервера]
 Kb tranferred (received) - Подсчет входяшего трафика нужен для контроля утелизации сети [Kb tranferred (received)] [Сервис: Shop/MES/CRM] [Элемент инфрастрктуры: DB/APP/QUEUE/LB и т.д.] [Имя сервера]
 Kb provided (sent) Подсчет исходящего трафика нужен для контроля утелизации сети [Kb provided (sent)] [Сервис: Shop/MES/CRM] [Элемент инфрастрктуры: DB/APP/QUEUE/LB и т.д.] [Имя сервера]

 5.2 Системный - эта часть мониторинга необходима для контроля работы систем: PostgreSQL, RabbitMQ,S3
 Метрики:  
 RPS - количество запросов к сервису в секунду. Метки: [RPS] [Сервис: Shop/MES/CRM] [Система: DB/APP/QUEUE/LB и т.д.]
 Response time - Время ответа Сервиса, по даннйо метрике косвено судить о нагруженности Системы, если среднее время растет значит система пергружена
                 Метки [Response time] [Сервис: Shop/MES/CRM] [Система: DB/APP/QUEUE/LB и т.д.]
 Error Rate - количество ошибок возврящаемых системой, позволяет определить здоровье сервиса.
                 Метки [Error Rate] [Сервис: Shop/MES/CRM] [Система: DB/APP/QUEUE/LB и т.д.]  

 5.3  Прикладной слой - контролирует показатели работы самих сервсисов: Онлайн Магазин, CRM, MES  
Метрики:
 Number of HTTP 200 - Количество ответов с кодом 200. Позволяет оценить количество корректных ответов [HTTP 200] [Сервис: Shop/MES/CRM]
 Number of HTTP 500 - Количество ответов с кодом 500. Позволяет оценить количество ответов с ошибкой сервера [HTTP 500] [Сервис: Shop/MES/CRM]
 Number of HTTP 404 - Количество ответов с кодом 404. Позволяет оценить количество ответов с неверным запросом  [HTTP 404] [Сервис: Shop/MES/CRM]
 RPS - Общее Количество  запросов к сервису в секунду.   [RPS] [Сервис: Shop/MES/CRM]
 Response time - Время ответа. Позволяет оценить отзывчивость сервиса.   [Response time] [Сервис: Shop/MES/CRM]
 Специфичные для сервисов метрики Позволяет определить Насыщеность сервиса. Так же могут являтся бизнес метриками.
 CRM - 
  Количество созданых за единицу времени заказов  Метки [Order Init Reate] [CRM] 
  Количество выполненых заказов за еденицу времени [Order Rady Reate] [CRM] 
  и т.д.
 MES 
  Количество моделей поступивших в расчет за еденицу времени [Model Init Reate] [MES] 
  Количество выполненых расчетов за еденицу времени [Model complite Reate] [MES] 
  Время выполнения расчета  [Model complite time] [MES]
  Количество моделей в очереди  [Model queue Reate] [MES]
  и т.д.
