Мотивация:
Без трейсинга очень сложно диагностировать плавающие проблемы, трудно или невозможно проследить путь и место единичного сбоя.
Трейсинг поможет выявить узкие мета процесса и архитектуры. Поможет разработчикам увидеть весь путь запросов пользователей.

Предлагаемое решение:
Для сбора телеметрии предлагается использовать SDK OpenTelemetry для отправки данных трейсинга и ПО Jaeger для сбор и анализа этих данных.
В качестве БД для ПО Jaeger будет использоваться Open Search.
Схема решения: https://github.com/Adeptgt/architecture--alexandrite/blob/descision/Task3/jewerly_c4_model.drawio

Компромиссы:
Трейсингом не охвачена очередь RabbitMQ т.к. доработка коробочного продукта не целесообразна и несет риски снизить надежность и производительность.

Безопасность: 
1. Организация подключения только по HTTPS и только внутри сети компании.
2. Доступ только сотрудникам Поддержки с активной УЗ
3. Логгирование фактов входа и действий сотрудников поддержки в системе.
