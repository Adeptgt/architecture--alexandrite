Мотивация:
Логирование позволит анализировать качество работы приложения. Фиксировать ошибки в работе приложения. Оперативно реагировать на возникающие проблемы. Проводить диагностику и пост аварийный анализ.
Прежде всего логирование необходимо добавить для компонентов которые подвержены изменениям. И в тех с которыми непосредственно взаимодействуют сотрудники и пользователи.
В данном случае это: Онлайн Магазин, CRM, MES

Предлагаемое решение:
Для приема, анализа и хранения логов предлагается использовать форк ELK OpenSearch в кластерной конфигурации так как он распространяется под лицензией Apache 2.0.
Визуализация будет настроена в Kibana
Доступ к логам с пром контура будут иметь только сотрудник поддержки и разработчики. 
Для каждой системы будет отдельный индекс. Ротация логов будет настроена по времени, хранится будут 180 дней. Этого периода достаточно как для оперативной реакции и разбора аварий, так и для бизнес анализа изменения показателей. Размер логов на данном этапе точно оценить сложно, на первом этапе будет развернута минимальная инсталляция кластера. Далее при необходимости будут вводится новые ноды для хранения данных. 
Анализ логов:
Необходимо настроить анализ резких изменений отслеживаемых параметров, например Резкое снижение/увеличение заказов. 
При обнаружении таких аномалий должны формироваться уведомления сотрудникам поддержки по почте и в мессенджеры/SMS

Перечень логов с Уровнем INFO
Онлайн Магазин:
События: Регистрация,Авторизация,Создание Заказа,Изменение статуса заказа,Загрузка модели.
CRM:
События: Вход пользователя, Изменение статуса заказа,Оплата
MES:
Вход сотрудников, Формирование заказа через API, Изменение статуса заказа.

Состав лога:
[Метка времени][Уровень лога: INFO][Система][Событие][Идентификатор пользователя][Дополнительная информация в зависимости от типа лога: номер заказа и т.д. ]
